# 2BECOME1 V0.3 — Workspace Implementation Plan

**Audience:** Hermes (implementation owner)  
**Baseline:** `main` at `b239275`  
**Target:** V0.3 local creative workspace  
**Status:** Approved implementation specification; execute phase by phase

## 1. Mission

Turn the working V0.2 vertical slice into a persistent, coherent local music
workspace. A user should be able to acquire permitted media, understand its
analysis, reuse it from a library, place two sources precisely, audition stems,
render, follow every long-running operation, recover from failure, and return
later without reconstructing the session.

V0.3 is successful when 2BECOME1 feels like one product rather than a web page
over several audio helpers.

The release must preserve these existing truths:

- processing and media stay on the user's machine;
- the browser and API remain same-origin by default;
- the service layer, CLI, and web routes share Python functions rather than
  wrapping one another's printed output;
- GPU-heavy Demucs work is serialized;
- fallbacks are labeled honestly (center/sides are not called vocals);
- analysis is presented as a suggestion and remains manually correctable;
- tracks must be owned by the user or used with permission.

## 2. Release definition of done

V0.3 is not done until all of the following work end to end:

1. YouTube import returns a job immediately instead of holding an HTTP request
   for the duration of `yt-dlp`.
2. Import progress shown in the UI comes from real `yt-dlp` output and includes
   stage, percentage when known, speed, ETA, cancellation, retry, and resume.
3. Local uploads show browser upload progress, then transition into the same
   analysis job model as YouTube imports.
4. Previously imported tracks are searchable, playable, reusable, editable,
   and safely removable from a proper Media Library.
5. The selected anchor and lead survive a refresh as part of an auto-saved
   project.
6. Both tracks have interactive waveforms with keyboard-accessible cue and
   render-region controls.
7. Detected BPM, key, beat, and downbeat remain visible as detected values;
   user overrides can be applied or cleared without destroying provenance.
8. A track can be separated in the UI, each truthful stem can be auditioned
   and downloaded, and an available stem can be selected as the lead source.
9. Preview and full-render jobs expose queued/running/complete/failed/cancelled
   states through the same Activity UI and SSE contract.
10. Every primary flow has designed empty, loading, success, failure, offline,
    cancellation, and restart-recovery states.
11. Desktop, tablet, and phone layouts are usable with keyboard, pointer, and
    touch; WCAG AA contrast and reduced-motion behavior are verified.
12. V0.2 databases migrate in place, the full automated suite passes locally,
    and GitHub Actions is green on the release commit.

## 3. Scope boundaries

### In V0.3

- asynchronous local-file and YouTube acquisition;
- managed media library, provenance, metadata, artwork, and waveform peaks;
- persisted projects and arrangement settings;
- analysis overrides and beat/downbeat cue correction;
- Demucs four-stem or honest center/side separation, caching, audition, and
  download;
- single selected lead source: full mix or one available stem;
- preview/full render queue, cancellation between safe stages, retry, history,
  playback, and download;
- a full responsive UI shell with Library, Studio, Activity, and Engine views;
- health/capability reporting and safe network-exposure messaging.

### Explicitly not in V0.3

- Pirate Bay or general torrent download controls in the web UI;
- DRM bypassing, cookies/account scraping, playlists, or bulk downloading;
- arbitrary remote URLs beyond validated YouTube links;
- cloud processing, Vercel processing, accounts, collaboration, or public
  hosting;
- a full DAW timeline, automation lanes, multi-track composition, or arbitrary
  multi-stem mixing;
- automatic phrase/chorus detection, lyrics, transcription, or generative AI;
- pretending stage-based Demucs progress is a measured percentage.

The existing torrent search helper may remain an explicitly experimental
CLI-only utility. Archive.org/public-domain discovery can be designed later as
a separate lawful-source feature; it must not delay V0.3.

## 4. Product structure and navigation

Use one same-origin application with four first-class views. Do not adopt a
frontend framework or build pipeline for this release. Split the existing
JavaScript into native ES modules and keep FastAPI serving static assets.

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 2BECOME1     Studio   Library   Activity             CUDA · LOCAL  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Active view                                                        │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│ Now playing / active job                         Help · Engine      │
└─────────────────────────────────────────────────────────────────────┘
```

### Studio

The creative workspace. It contains the project title/status, two source decks,
alignment timeline, musical plan, mix controls, preview, and final render.

### Library

All managed tracks. It supports search, source filters, sort, list/grid density,
playback, metadata inspection, selection into either deck, rename, analysis
override, separation, trash, and restore.

### Activity

One chronological view of imports, separations, previews, and full renders.
Active jobs stay at the top. Each item owns its progress, current stage,
cancellation/retry action, result, and useful failure explanation.

### Engine

Local capabilities and storage: application version, ffmpeg/ffprobe/yt-dlp,
Demucs availability, preferred/current device, data directory, disk usage,
queue state, network binding warning, and troubleshooting copy. This is status,
not a sprawling settings system.

## 5. Core UX flows

### 5.1 Start or resume a project

- On first use, create an `Untitled mix` project and show a short, dismissible
  local-first introduction.
- On return, reopen the most recently updated project and restore selected
  tracks, source variants, cue points, duration, gains, and pitch behavior.
- Show a small `Saving…` then `Saved locally` indicator; debounce project writes.
- Provide `New mix`, project rename, and recent-project switching.
- Never discard an existing selection just because the user opens the source
  picker or cancels an import.

### 5.2 Choose media for a deck

Every deck's `Choose`/`Replace` action opens one source picker rather than
embedding competing controls in the deck.

```text
┌─ Choose the foundation ────────────────────────────────────────┐
│ [Library] [Upload] [YouTube]                                  │
│                                                               │
│ Search existing tracks…                                       │
│ ┌ track row ──────────────────────────────── Use track ┐       │
│ └──────────────────────────────────────────────────────┘       │
│                                                               │
│                           Cancel                               │
└───────────────────────────────────────────────────────────────┘
```

- Library is the default tab when tracks exist.
- Upload supports click, drag-and-drop, and multiple files from the Library
  view; from a deck, the first successful track is assigned to that deck.
- YouTube validates before submission, states `one video only`, and includes
  the rights/permission reminder without legalistic alarm copy.
- Closing the picker does not cancel an active import. The job continues in
  Activity and may be assigned when complete.
- Completed imports are added to the library exactly once through content
  deduplication.

### 5.3 Work with the two decks

Each ready deck shows:

- artwork or generated source-colored placeholder;
- editable display title and source provenance;
- audio transport, current time, duration, and waveform;
- detected/effective BPM and key with confidence;
- beat and suggested-downbeat markers;
- chosen source variant (`Full mix`, `Vocals`, `Drums`, `Bass`, `Other`,
  `Center`, or `Sides` as actually available);
- actions: Choose/Replace, Edit analysis, Separate, Open in Library, Clear.

A central swap button exchanges anchor and lead, including cue/settings that
belong to the deck role. It must not alter the underlying track records.

### 5.4 Correct analysis and place cues

- Clicking or keyboard-seeking on a waveform updates the playhead only.
- `Set cue here` explicitly changes the cue; accidental clicks must not rewrite
  project settings.
- Cue markers snap to the detected beat grid by default and can be moved freely
  while holding an `unsnapped` modifier/action.
- Numeric fields remain available for exact entry to 0.1 seconds.
- Analysis editor shows detected BPM/key and separate override fields.
- `Reset to detected` removes overrides.
- Low-confidence analysis is visually labeled `Check this`, not `Wrong`.

### 5.5 Separate and select stems

- `Separate stems` creates a queued separation job and opens the Activity item.
- UI copy distinguishes `Demucs · CUDA`, `Demucs · CPU`, and `Center/side
  transform`; never display a center channel as an isolated vocal.
- Completed stems appear in a tray with individual play/stop, `Use as lead`,
  and download actions.
- Cache by track content hash plus method/model so repeated renders do not
  rerun Demucs.
- Only one GPU separation/render task executes at once.
- Cancellation is best-effort: queued jobs cancel immediately; active Demucs
  jobs may say `Stopping after the current stage` if interruption is unsafe.

### 5.6 Arrange and preview

Use stacked waveforms sharing a visible output-region width. The lead waveform
still represents source time; label the computed stretch rather than implying
it has already been destructively transformed.

Controls are grouped by user intent:

- **Timing:** anchor cue, lead cue, duration, snap to suggested downbeats;
- **Harmony:** match anchor key or preserve original lead pitch;
- **Source:** full mix or selected stem;
- **Mix:** anchor and lead gain with numeric values and reset;
- **Plan:** tempo ratio, BPM change percentage, semitone shift, selected
  variants, expected output duration, and warnings.

`Preview 12s` is the primary iteration action. `Render full mix` is distinct
and requires no confirmation unless duration is unusually long.

### 5.7 Follow, recover, and use results

- The global Activity button shows an active-count badge and opens a drawer on
  Studio or the full Activity view from navigation.
- SSE reconnect falls back to polling and stops polling on all terminal states.
- A failed job preserves its request and offers `Retry` plus a plain-language
  error and expandable technical details.
- A completed render provides play, download, rename, reveal-data-folder
  instructions, and `Use these settings in a new mix`.
- On server restart, previously running jobs become `interrupted`, not generic
  failures; resumable imports offer `Resume`, while renders offer `Retry`.

## 6. Visual and interaction system

Retain the existing dark, playful 90s-pop identity. Upgrade hierarchy and
density rather than replacing the brand with a generic dashboard.

### Design tokens

- Anchor: pink; lead: cyan; active/success: lime; waiting: orange; destructive
  or failed: accessible red.
- Define all colors, spacing, radii, shadows, type sizes, focus rings, and
  animation durations as CSS custom properties.
- Use a restrained type scale. The V0.2 hero may remain on an empty project but
  must collapse to a compact project header once work begins.
- Keep decorative grain/glow behind content and disable costly blur/grain when
  `prefers-reduced-motion` or constrained mobile layouts warrant it.

### Responsive behavior

- `>= 1100px`: two decks side by side, persistent plan/mix sidebar where useful.
- `700–1099px`: stacked decks with compact navigation and full-width arranger.
- `< 700px`: single-column cards, bottom sticky Preview/Render bar, source picker
  as a full-screen sheet, no controls requiring hover.
- Minimum touch target: 44×44 CSS pixels.

### Accessibility requirements

- Semantic landmarks, headings, forms, buttons, dialogs, tables/lists, and
  `aria-live` only where status changes require announcement.
- Dialog focus trap, Escape close, focus restoration, and visible focus rings.
- Every waveform action has equivalent buttons and numeric inputs.
- Do not use color alone for source, confidence, or job status.
- Respect `prefers-reduced-motion`; animation must never convey required state.
- Escape or assign with `textContent`; never interpolate filenames, titles,
  URLs, job errors, or metadata into `innerHTML`.

## 8. Backend architecture

Extract job orchestration from `studio.py` instead of growing that file further.

```text
src/twobecomeone/
├── studio.py          # library/projects facade and compatibility methods
├── jobs.py            # lifecycle, executors, cancellation, retry, SSE state
├── acquisition.py     # upload staging, yt-dlp parsing, metadata/artwork
├── media.py           # hashes, waveform peaks, tags, safe managed paths
├── projects.py        # project persistence and validation
├── webapp.py          # validation and HTTP mapping only
└── ...existing DSP modules unchanged unless a phase requires it
```

### Executors and resource policy

- `acquisition_executor`: two workers for downloads/analysis of separate tracks.
- `audio_executor`: one worker for Demucs, previews, and renders. This preserves
  the laptop's 6 GB GPU headroom and avoids competing ffmpeg/Demucs work.
- Store cancellation tokens per running job behind a lock.
- Keep the active `yt-dlp` process handle so cancellation can terminate it and
  retain the deterministic partial download for resume.
- Do not hold a database transaction while downloading, analyzing, separating,
  or rendering.
- Shut down cleanly: stop accepting new work, request cancellation of
  cancellable acquisition processes, and let unsafe-to-interrupt audio stages
  finish or become `interrupted` on restart.

### Honest progress model

- YouTube download: parse machine-readable `yt-dlp --newline
  --progress-template` output for measured percent/bytes/speed/ETA.
- Upload: browser reports transfer percentage; backend reports staging,
  validating, analyzing, waveform, and finalizing stages.
- Analysis/waveform: stage completion, not invented fractional precision.
- Demucs: stage labels unless the API exposes a dependable callback; never
  animate a fake numeric percentage as measured work.
- Render: planning/separating/aligning/mixing/loudness/finalizing stage weights
  may drive an explicitly stage-based progress bar.

## 9. Persistent data and migrations

Add a `schema_migrations(version INTEGER PRIMARY KEY, applied_at REAL)` table and
move future migrations to numbered, transactional functions. A V0.2 database
fixture must be migrated in tests.

### Extend `tracks`

- `display_name TEXT` (fall back to `original_name`);
- `content_sha256 TEXT` with an index for deduplication;
- `metadata_json TEXT` for artist/album/source metadata;
- `artwork_path TEXT` and `waveform_path TEXT` constrained to managed roots;
- `bpm_override REAL`, `tonic_override TEXT`, `mode_override TEXT`;
- `first_beat_override REAL`, `downbeat_override REAL`;
- `deleted_at REAL` for reversible trash.

Keep detected values in the existing columns. Top-level API `bpm`, `key`, and
`beat_grid` return effective values; include a `detected` object so the UI can
show and reset overrides.

### Extend `jobs`

- supported kinds: `import`, `separate`, `preview`, `render`;
- supported states: `queued`, `running`, `complete`, `failed`, `cancelled`,
  `interrupted`;
- add `executor TEXT`, `cancel_requested INTEGER DEFAULT 0`, and
  `parent_job_id TEXT` where a render depends on separation;
- keep request/result/error JSON and current stage/progress for reconnectable UI.

### Add `projects`

- `id`, `name`, `anchor_track_id`, `lead_track_id`;
- `anchor_variant`, `lead_variant`;
- `settings_json` containing cues, duration, gains, snap, and pitch mode;
- `created_at`, `updated_at`.

Validate every referenced track and variant in the service layer. Auto-save
updates use optimistic `updated_at` conflict detection or last-write-wins in the
single-user local process; document the chosen behavior.

### Add `stem_sets`

- `id`, `track_id`, `method`, `model`, `device`, `status`;
- `paths_json`, `created_at`;
- unique cache key over track content hash + method/model.

### Derived files

- `artwork/<track-id>.webp`;
- `waveforms/<track-id>.json` containing normalized min/max peaks (target 1,200
  bins, versioned payload);
- existing `tracks/`, `incoming/`, `stems/`, and `renders/` remain.

Trash hides a track but does not immediately remove media needed by an existing
project. Permanent purge is an Engine/Library action with explicit confirmation
and strict managed-path checks.

## 10. API contract

Keep V0.2 endpoints working during migration. Add specific endpoints rather
than forcing all behavior through ambiguous `POST /api/jobs`.

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/health` | capabilities, versions, queue/storage status |
| `GET` | `/api/tracks` | paginated search/filter/sort library |
| `GET` | `/api/tracks/{id}` | complete effective/detected track model |
| `PATCH` | `/api/tracks/{id}` | display name and analysis overrides |
| `DELETE` | `/api/tracks/{id}` | move to reversible trash |
| `POST` | `/api/tracks/{id}/restore` | restore trashed track |
| `GET` | `/api/tracks/{id}/audio` | range-capable inline audio |
| `GET` | `/api/tracks/{id}/artwork` | local artwork or generated placeholder |
| `GET` | `/api/tracks/{id}/waveform` | versioned normalized peak data |
| `POST` | `/api/imports/upload` | stage upload and return import job |
| `POST` | `/api/imports/youtube` | validate URL and return `202` import job |
| `POST` | `/api/tracks/{id}/separations` | queue cached/new separation |
| `GET` | `/api/tracks/{id}/stems` | list truthful available stems |
| `GET` | `/api/stems/{id}/audio` | audition/download a managed stem |
| `GET/POST` | `/api/projects` | list/create projects |
| `GET/PATCH/DELETE` | `/api/projects/{id}` | load/save/delete a project |
| `POST` | `/api/renders` | queue preview or full render |
| `GET` | `/api/jobs` | filterable activity feed |
| `GET` | `/api/jobs/{id}` | current job snapshot |
| `GET` | `/api/jobs/{id}/events` | SSE updates plus heartbeat |
| `POST` | `/api/jobs/{id}/cancel` | request truthful cancellation |
| `POST` | `/api/jobs/{id}/retry` | clone a valid failed/interrupted request |
| `GET` | `/api/jobs/{id}/audio` | backward-compatible completed output |

Response rules:

- one JSON error envelope: `{ "error": { "code", "message", "detail" } }`;
- `400` invalid user input, `404` missing, `409` state conflict, `413` upload
  limit, `422` validation, `503` missing capability;
- list endpoints return `items`, `total`, `limit`, and `offset`;
- job POSTs return `202` and a complete initial job snapshot;
- never return internal absolute paths except `data_dir` from the local health
  endpoint; provenance may return a sanitized source label and permitted URL.

## 13. Security and failure rules

- Default bind remains `127.0.0.1`.
- Binding a non-loopback host requires an explicit `--allow-network` flag and
  prints a prominent no-auth warning; Engine shows a persistent warning banner.
- Accept only allowed audio suffixes plus successful ffmpeg decode; never trust
  MIME type or uploaded filename.
- Retain the 750 MB upload ceiling and enforce a configurable download ceiling
  where yt-dlp can report size before transfer.
- Use subprocess argument lists, never shell strings.
- Sanitize external stderr before returning it to the browser; retain fuller
  local diagnostic detail where safe.
- Validate all media/artwork/waveform/stem/render paths against their dedicated
  managed root before serving, trashing, or purging.
- No untrusted HTML injection in the browser.
- Job cancellation and shutdown must not leave database rows claiming success
  or half-written files in final managed directories.

## 14. Performance budgets

- Initial HTML/CSS/JS transfer below 350 KB uncompressed, excluding audio and
  artwork; avoid a framework bundle.
- Library first page renders 100 tracks without blocking interaction; paginate
  beyond that.
- Waveform JSON target below 40 KB per track and cacheable by ETag.
- YouTube job creation responds in under one second before network download.
- UI interaction feedback begins within 100 ms; long work always produces a
